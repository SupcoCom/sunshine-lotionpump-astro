# Architecture decision record

## ADR-1 — WordPress stays, the theme goes

**Decision:** WordPress remains the content store and the only place leads are processed.
Astro renders everything statically at build time.

**Why:** The site's value is its content (57 products with 30 spec fields each, 23 long-form
articles, 13 hand-built landing pages) and its lead pipeline (CF7 → WP Mail SMTP → Flamingo →
HubSpot). Neither has to change. What has to go is the *rendering* layer: Elementor 4.3.2 +
Elementor Pro 4.2.1 + Hello Elementor + jQuery, which cost ~600 KB of CSS/JS per page and a
PHP render on every cache miss.

**Consequence:** Content editors keep using wp-admin. Layout changes require a rebuild, which is
the trade-off this project accepts (see ADR-4).

## ADR-2 — URL parity over information architecture

**Decision:** Reproduce the legacy permalinks exactly, including the odd ones
(`/category/blog/<slug>/`, `/product/<slug>/`, `/products/`).

**Why:** The site ranks for B2B pump keywords and runs Google Ads against those URLs. Any URL
change is a ranking and conversion risk. A "cleaner" IA would be a migration project, not a
rebuild.

**Consequence:** One catch-all route (`src/pages/[slug].astro`) serves every root-level URL from
a registry generated by the sync script. Adding a page in WordPress is enough to get a route.

## ADR-3 — Content is generated at build time, not fetched at runtime

**Decision:** `scripts/sync-wp.mjs` pulls the whole content model out of the REST API and writes
JSON + Markdown + HTML into `src/`. Astro imports it statically.

**Why:** Static output means the site can be served from a CDN with no origin, no PHP and no
database. It also means a content change requires a rebuild — which is exactly what a
publish-triggered CI job does.

**Consequence:** `npm run sync` must run before every build. `npm run build` does this
automatically.

## ADR-4 — Landing pages are ported verbatim, not re-authored

**Decision:** The 13 `*-manufacturer-landingpage` pages are copied as-is. Only their Contact Form
7 markup is replaced by a marker that the form component fills.

**Why:** Those pages are the money pages — they are the Google Ads final URLs and were
hand-tuned over months. Re-authoring them would risk conversion rate and would be unverifiable
against the original. Their CSS is scoped to `.lp-wrap`, so it cannot leak into the rest of the
site.

**Consequence:** The form component has an `lp` variant that emits the exact class contract the
landing pages already style (`.wpcf7-form`, `.lp-form-field`, `.lp-form-submit`), so the forms
look identical to before.

## ADR-5 — One lead form, one edge endpoint

**Decision:** Every form on the site is the same component posting to `/api/lead`, a single
Cloudflare Worker function that validates and forwards to the WordPress Contact Form 7 REST
endpoint.

**Why:** A static host cannot run PHP. Reusing the existing CF7 form means the client's email,
Flamingo archive and HubSpot sync keep working with zero changes — including the `lp-group`
source field the HubSpot snippet reads.

**Consequence:** The only dynamic route in the build. If WordPress is down, leads fail loudly
(the endpoint returns 502 with a "email us directly" message) rather than silently.

## ADR-6 — SEO metadata is snapshotted from the live site

**Decision:** The sync script fetches the rendered `<head>` of all 109 indexable URLs and stores
title / description / canonical / robots / OpenGraph. Pages render those values verbatim.

**Why:** Rank Math was generating titles and descriptions with its own logic. Re-deriving them
would change SERP snippets overnight. Copying them is the only zero-risk option.

**Consequence:** A handful of objectively broken values (e.g. the privacy policy description was
the literal string `Last updated: August 19, 2026`) are corrected in `SEO_OVERRIDES` in
`src/lib/content.ts`. Everything else is byte-identical to what was live.

## ADR-7 — No build-time image pipeline

**Decision:** Images are plain `<img>` tags pointing at the existing CDN
(`img.supcous.com`) and WordPress uploads.

**Why:** The images are already webp and already on a CDN. Running 354 images through an optimizer
at build time would add minutes to every build and a dependency on a remote image service, for
no measurable gain.

**Consequence:** The site still depends on WordPress being reachable for images. Mirroring media
to R2/Cloudflare Images is a documented follow-up (see `docs/DEPLOYMENT.md`).

## ADR-8 — Company identity is centralised

**Decision:** Brand, legal name, address, phone, email and marketing claims live in
`src/config/site.ts`. Every page reads from there.

**Why:** The legacy site published three different legal names, two different cities and four
different founding years. That is a trust and E-E-A-T problem, and it is impossible to fix
consistently when the values are copy-pasted across 20 Elementor pages.

**Consequence:** One place to correct. Every conflicting value found on the old site is recorded
in `docs/CONTENT-AUDIT.md` with its location, so the owner can confirm the single truth.
